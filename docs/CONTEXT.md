# 꾸로록 프로젝트 맥락

> 꾸로록(Kkurolog) = '거꾸로캠퍼스'의 **꾸로** + 기록을 뜻하는 **Log**
>
> **거캠에 이미 있는 사람들의 경험을 기록하고, 학생이 필요할 때 질문으로 꺼내볼 수 있게 한다.**
> 슬로건: *한 사람의 경험이 다음 학생의 선택지가 되도록.*

## 누구를 위한 서비스인가
- **사용자**: 거꾸로캠퍼스 재학생 약 70명. 거꾸로캠퍼스는 일반 고등학교와 다른 교육과정을 운영하는 대안교육기관이다.
- 졸업을 **Exit(엑시트)**라고 부른다.
- 졸업 후 진로가 다양하다: 국내·해외 대학, 취업, 인턴십, 창업, 예술·디자인·개발, 대학에 바로 가지 않는 경로, 취업·창업 후 진학 같은 복합 경로.
- 재학생 상당수가 **미성년자**다. 개인정보와 졸업생 연결 방식에 특히 신경 쓴다.

## 문제 정의
- 처음 가설은 "진로 상담과 졸업생 연결이 부족하다"였다.
- 조사해 보니 자원은 이미 많았다: 팀 코치, 진로·진학 전문 '몰라' 코치, 졸업생 네트워크, 홈커밍데이, '나가서 뭐하니', 외부 전문가 연결, 졸업생 인터뷰 아카이브, G-School AI.
- 그래서 진짜 문제는 이것이다.
  **답을 가진 사람과 경험은 이미 있지만, 필요한 학생이 필요한 순간에 찾고 발견하기 어렵다.**
- 졸업생의 '결과'는 어느 정도 기록되어 있다. 하지만 **왜 그 선택을 했는지, 어떤 고민·실패·시행착오가 있었는지, 무엇이 실제로 도움이 됐는지, 다시 한다면 무엇을 바꿀지**는 사람 안에만 남아 있다. 꾸로록은 바로 이 부분에 집중한다.

## 설문 결과 (재학생 50명)
| 항목 | 결과 |
|---|---|
| 도움받고 싶은 대상 | 비슷한 고민을 먼저 한 졸업생 54%, 코치진 48%, 외부 전문가 46% |
| 도움 요청이 어려운 이유 | 직접 연락이 부담 44%, 누구에게 물을지 모름 40%, 필요한 도움을 설명하기 어려움 32% |
| 원하는 기능 (4~5점) | 진학·졸업생 사례 한곳에서 확인 84%, 졸업생·전문가 탐색·연결 82%, 거캠 맞춤 AI 챗봇 68% |

→ 핵심 가치는 AI 챗봇 자체보다 **"거캠의 경험 데이터 + 사람 연결"**이다.

## G-School AI와의 차이
- G-School AI는 진학 대학, 프로젝트·수상·창업·취업 사례 같은 **결과·정량 정보**를 이미 잘 답한다.
- 꾸로록은 "더 잘 설명하는 챗봇"이 목표가 아니다. **선택의 과정과 맥락**을 다룬다.
  - 기존 정보: "A 졸업생은 창업 후 태재대학교에 진학했다."
  - 꾸로록: "왜 창업을 먼저 택했나? 대학을 다시 고민한 계기는? 가장 어려웠던 선택은? 거캠의 어떤 경험이 도움이 됐나?"
- 차별점은 RAG 기술이 아니라 **거캠 구성원의 암묵적 경험을 얼마나 깊이 데이터로 만들고 다시 발견할 수 있게 하느냐**다.

## 서비스 흐름 (최종 목표)
1. 학생이 자유롭게 질문한다.
2. **경험 질문**이면 졸업생·코치 인터뷰에서 관련 구간을 찾는다. LLM은 그 근거 안에서만 답하고, 출처를 함께 보여준다. 출처를 누르면 인터뷰의 해당 구간과 앞뒤 맥락을 볼 수 있다.
3. **정량·사실 질문**은 핵심 기능이 아니다. 필요하면 최소한의 구조화 데이터만 쓴다.
4. **근거가 부족하면** 지어내지 않는다. "현재 자료만으로는 답하기 어려워요. 비슷한 경험을 가진 사람을 찾아볼까요?"라고 안내하고 멘토 추천으로 연결한다.
5. **멘토 연락**은 학생 → 꾸로록 → 졸업생 형태로 첫 연락을 전달한다 (MVP는 이메일). 졸업생이 별도 서비스에 계속 로그인해야 하는 구조는 피한다.

## 데이터와 기술 구상
- 데이터 종류와 공개 등급은 [DATA.md](./DATA.md)에 정리한다. 실제 데이터는 아직 학교에서 받는 중이라, 지금은 **demo 데이터**로 틀만 만든다.
- RAG 파이프라인 구상: 인터뷰 원문 → 개인정보 정제 → 주제 단위 chunking → metadata 부착 → OpenAI 임베딩 → Supabase pgvector 저장 → 질문 임베딩 → 유사도 검색 Top-K → 근거 충분성 판단 → Claude로 근거 기반 답변 → 사용한 출처 반환

## 팀과 목표
- 대학생 약 6명, 약 2개월. 역할: 기획, 디자인, 프론트엔드, 백엔드, 데이터 수집·정제, RAG/AI (경계는 유연함).
- 목표는 상용 서비스가 아니라 **실제로 동작하고 사용자 가치를 검증할 수 있는 프로토타입**이다.

## 프로젝트 원칙
1. 화려한 기술보다 **실제로 작동하는 MVP**를 만든다.
2. RAG 자체를 차별점이라고 주장하지 않는다. 차별점은 **거캠의 실제 경험 데이터**다.
3. 데이터에 없는 내용을 AI가 **지어내지 않는다**. 가능하면 출처를 함께 준다.
4. 인터뷰 원문 공개 범위와 개인정보는 따로 관리한다. 멘토는 **동의한 졸업생만** 노출한다.
5. 복잡한 내부 메시징, 과한 아키텍처, 불필요한 유료 서비스는 피한다. **무료 플랜**을 우선한다.
