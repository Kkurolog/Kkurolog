# 공개 등급을 L1 → L3로 올리기 (제안, 팀 확인 전)

> 작성일 2026-11-18 · 아직 실행하지 않았다. 이 문서는 "무엇을, 어떤 순서로 해야 안전한가"를 적은 것이다.

## 무엇을 하려는가

인터뷰 글 39개(gschool.kr "Exit 오깔")의 공개 등급을 L1(익명, 답변 근거로만)에서 L3로 올린다. 그러면 답변에서

- 선배 별명이 보인다 (카드 제목이 "○○ 선배"가 된다)
- "2023년 10월 글 · “글 제목”"이 링크가 되어, 누르면 원문 글이 새 탭으로 열린다
- 출처 패널에 인터뷰 원문 구간이 보인다

## 근거

- 2026-11-18, 교장선생님이 사용을 허락했다: "답변은 모두 웹에 공개된 글을 바탕으로 하고, 그 글은 거캠 학생들이 보고 진로에 도움을 받으라고 쓴 것이니 모두 사용해도 된다." (백엔드 담당이 전달)
- 지금까지의 팀 기록은 서로 달랐다. `docs/DATA.md`·`docs/DECISIONS.md`(11-09)는 "허락 전이라 전부 L1", `docs/proposals/ask-plan.md`는 "허락받음". 이 문서로 정리한다.

## 그래도 지키는 것

- **실명은 어떤 응답에도 넣지 않는다.** 글 제목 39개 중 20개는 끝에 "- 실명 [별명]"이 붙어 있다. `backend/app/rag/pipeline.py`의 `strip_author`가 그 부분을 지운 제목만 내보낸다. 실제 제목 39개에 적용해 실명이 남지 않는 것을 확인했다(2026-11-18).
- 내부 ID(`person_id`), 연락처는 내보내지 않는다.
- 원문 페이지(gschool.kr)에는 글쓴이 이름이 나온다. 링크를 거는 것은 그 페이지로 안내하는 것이고, 꾸로록이 실명을 직접 보여 주는 것은 아니다.

## 실행 순서 ⚠️

순서를 바꾸면 실명이 화면에 나갈 수 있다.

1. **코드를 먼저 배포한다.** `strip_author`와 카드 화면이 들어 있는 브랜치(PR #19, 그리고 그 위의 `feat/retrieval-quality`)가 `main`에 합쳐져 Render·Vercel에 배포되어야 한다.
   - 지금 배포된 코드와 PR #19의 코드는 제목을 그대로 쓴다. 이 상태에서 등급만 올리면 "제목 - 실명 [별명]"이 답변 모델에게 넘어가고, PR #19 화면에서는 제목이 그대로 보인다.
2. **등급을 올린다.** `cd scripts && python run_sql.py ../supabase/migrations/0003_gschool_visibility_l3.sql`
   - 배포된 사이트가 같은 DB를 쓰므로 실행하는 즉시 실제 사용자에게 반영된다.
3. **확인한다.** 배포된 사이트에서 질문 2~3개를 넣어 별명·제목·원문 링크가 나오는지, 제목에 실명이 없는지 본다.
4. **문서를 고친다.** `docs/DATA.md`의 "전부 L1" 문장, `docs/DECISIONS.md`에 결정 한 줄, `backend/app/rag/intent.py`의 꾸로록 소개 문구(자료 출처·신뢰 설명에 "원문을 열어 볼 수 있어요"를 넣을 수 있게 된다).

되돌리기: 같은 SQL 파일 아래쪽에 L1로 돌리는 문장이 주석으로 있다.

## 함께 바뀐 것

- `scripts/build_dataset.py`의 등급 기본값을 L1 → L3로 바꿨다. 안 바꾸면 데이터를 다시 만들어 적재할 때 등급이 L1로 되돌아간다.

## 팀이 한 번 더 봐 줬으면 하는 것

- 허락의 범위: "모두 사용해도 된다"에 **원문 문장을 그대로 인용하는 것**까지 포함되는지. L3는 출처 패널에 원문 구간을 그대로 보여 준다.
- 졸업생 본인의 의사: 학교가 허락했더라도, 나중에 "내 글은 빼 달라"는 졸업생이 있으면 그 글만 L0(사용 불가)나 L1로 내릴 수 있다. 글 단위로 등급을 따로 줄 수 있게 되어 있다.
- 새 글을 추가할 때: 제목 모양이 다르면 `strip_author`가 실명을 못 지울 수 있다. 적재 뒤에 "실명이 남은 제목이 없는지" 확인하는 단계를 `scripts/check_tags.py` 같은 검사에 넣는 것을 제안한다.
