# 데이터 구조 초안

> ⚠️ **초안이며 팀 논의 후 수정한다.** 실제 데이터를 받아 보면서 바꿔 나간다.
> 인터뷰 원문과 개인정보는 **절대 git에 올리지 않는다** (`data/raw/`는 .gitignore에 포함됨).

## 1. Experience DB: 인터뷰 chunk (가장 중요)

인터뷰 원문을 주제 단위로 잘라(chunk) 저장한다. chunk마다 아래 metadata를 붙인다.

| 필드 | 설명 | 예시 |
|---|---|---|
| `interview_id` | 원본 인터뷰 ID | `itv-2024-003` |
| `alumni_id` | 졸업생 ID (실명이 아닌 내부 ID) | `alm-017` |
| `career_field` | 진로 분야 | 국내 대학 / 해외 대학 / 취업 / 창업 / 예술·디자인 / 개발 / 갭이어 / 복합 |
| `period` | 시기: 경험한 시점이나 인터뷰 시점 | `재학 중`, `엑시트 직후`, `엑시트 3년 차`, `2024` |
| `topic` | 주제 | 선택 이유 / 고민 / 실패 / 전환점 / 도움된 것 / 조언 |
| `source_location` | 원문 위치 (출처를 눌렀을 때 앞뒤 맥락을 찾는 용도) | 파일명 + 문단 번호나 시간 |
| `visibility` | 공개 등급 (아래 표) | `L1` |
| `source_type` | 자료 종류 | 졸업생 인터뷰 / 나가서 뭐하니 / 홈커밍 / 코치 인터뷰 / 매뉴얼 |

현재 `/ask` 응답의 `sources`는 이 중 일부(`interview_id`, 화면용 이름, 발췌)만 쓴다.

## 2. 공개 등급 초안

| 등급 | 의미 | 답변 근거로 사용 | 원문 구간 노출 | 실명·멘토 연결 |
|---|---|---|---|---|
| **L0** | 사용 불가 | ✗ | ✗ | ✗ |
| **L1** | 익명으로 답변 근거만 | ○ | ✗ | ✗ |
| **L2** | 익명 원문 구간 노출 | ○ | ○ (익명) | ✗ |
| **L3** | 실명·멘토 프로필 연결 | ○ | ○ | ○ |

- 등급은 인터뷰 대상자의 동의 범위에 따라 정한다. 확실하지 않으면 더 낮은 등급으로 둔다.

## 3. Mentor/Profile DB: 멘토 프로필

**참여에 동의한 졸업생만** 저장하고 노출한다.

| 필드 | 설명 |
|---|---|
| 이름 또는 별명 | 공개할 이름 |
| 엑시트 연도 | 졸업 연도 |
| 진로 경로 | 진학 / 취업 / 창업 / 기타 (여러 개 가능) |
| 주요 경험 태그 | 예: `해외 대학`, `디자인`, `창업 후 진학` |
| 답변 가능 주제 | 예: 포트폴리오, 갭이어, 해외 지원 |
| 멘토 참여 동의 | 예/아니오 (아니오면 노출하지 않음) |
| 연락 가능 여부 | 지금 연락을 받을 수 있는지 |

- 연락처(이메일)는 학생에게 직접 보여주지 않는다. 꾸로록이 첫 연락을 전달한다.
- demo 데이터(`backend/app/data/mentors_demo.json`)의 필드 이름: `id`, `name`, `exit_year`, `career_paths`,
  `path_summary`(경로 한 줄 요약), `summary`(경험 요약), `tags`, `topics`, `consent`, `available`, `email`(내부 전용).
  `career_paths` 값은 `대학 진학 / 해외 대학 / 취업 / 창업 / 디자인·예술 / 개발 / 기타 경로` 중에서 고른다 (멘토 찾기 탭과 같음).

## 4. 최소 사실 데이터
기본 진로 경로, 인터뷰 시점, 주요 프로젝트, 출처 정보. 정량 정보는 핵심이 아니므로 최소한으로만 둔다.

## 5. 처리 흐름 (나중에 `scripts/`에서)
원문 → 개인정보 정제 → 주제 단위 chunking → metadata 부착 → OpenAI 임베딩 → Supabase pgvector 저장
