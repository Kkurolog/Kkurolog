# 태그 기준 문서

> 꾸로록 데이터(조각·인물)에 붙이는 태그의 **유일한 기준**이다.
> 데이터에는 이 문서 1~4장 표에 있는 `code`만 저장한다. 검사는 `python scripts/check_tags.py`로 한다.
> 예시 문장은 이해를 돕기 위해 지어낸 문장이다 (실제 인터뷰 원문은 git에 올리지 않는다).

## 기본 원칙
- **저장은 code, 표시는 한글 이름.** 데이터·DB에는 영어 snake_case `code`를 저장한다.
  화면과 검색용 `embed_text` 머리말에는 한글 이름을 쓴다.
- 종류마다 칸이 따로 있다.

  | 종류 | 저장 칸 | 단위 | 개수 | 기타(`etc`)일 때 상세 칸 |
  |---|---|---|---|---|
  | topic | `topics` | 조각 | 1~2개 | `topic_detail` |
  | career_path (경로) | `career_paths` | 인물 | 여러 개 | `path_detail` |
  | career_field (분야) | `career_fields` | 인물 | 여러 개 | `field_detail` |
  | speaker_type | `speaker_type` | 인물·조각 | 1개 | 없음 |

- **진로 태그(career_path, career_field)는 인물의 `as_of_date` 기준이다.** `as_of_date`는 인터뷰 게시일이다.
  그 날짜에 하고 있거나 이미 거친 것만 붙이고, 계획·희망만 있는 것은 붙이지 않는다 (계획은 조각의 `future_plan`이 담당).
- **경로의 순서는 태그가 아니라 `path_summary`가 담당한다.** 태그는 "무엇을 거쳤나"만 표시하고,
  "언제, 어떤 순서로"는 `path_summary` 한 줄에 쓴다. 예: `거캠 엑시트 → 검정고시 → 국내 대학 행정학과`
- 학교·기관·프로그램 이름(MTA LEINN, PaTI, 42 Seoul 등)은 태그가 아니다. 인물의 `organizations` 칸에 자유롭게 적는다.

## 기타(`etc`)와 승격 규칙
- 맞는 태그가 없으면 `etc`를 붙이고, 해당 상세 칸에 **구체적인 내용**을 적는다.
  상세 칸은 목록이다 (`["의학"]`, `["특성화고 재입학", "어학연수"]`).
  - `etc`를 붙였으면 상세 칸에 **아래 "상세 값 매핑" 표에 없는 값**을 하나 이상 반드시 적는다.
  - 상세 칸은 정식 태그를 보충하는 구체적인 내용(전공 이름 등)을 남기는 데도 쓸 수 있다 (`etc` 없이도 됨).
  - 상세 값이 "상세 값 매핑" 표에 있으면, 그 값에 해당하는 정식 태그도 반드시 붙인다
    (예: `field_detail`에 `사회학` → `career_fields`에 `humanities_social`).
  - 같은 내용은 같은 표현으로 짧게 쓴다 (예: "의학", "의대 진학", "의대"를 섞지 않고 `의학`으로 통일).
    표현을 맞춰야 승격 후보를 셀 수 있다.
- **승격 기준**: 같은 상세 값이 **career는 서로 다른 인물 3명 이상**, **topic은 조각 5개 이상**에서 나오면 정식 태그로 만든다.
  1. 이 문서의 해당 표에 새 태그를 추가하고 "변경 기록"에 남긴다.
  2. 그 상세 값을 가진 기존 데이터를 새 태그로 다시 태깅한다. 다른 `etc` 상세 값이 남지 않으면 `etc`는 지운다.
  3. 상세 값을 남겨 둘 경우(구체적인 전공 등) "상세 값 매핑" 표에 `상세 값 → code`를 추가한다.
     여러 상세 값을 묶어 하나의 태그로 만들 때도(예: 사회학·행정학 → `humanities_social`) 이 표에 적는다.
- 기준에 못 미치는 것(career 2명 이하, topic 4개 이하)은 새 태그로 만들지 않고 `etc` + 상세 칸으로 둔다.
- 승격 후보는 `python scripts/check_tags.py`가 보여준다. (`etc`가 붙은 데이터의, 매핑 표에 없는 상세 값만 센다)
- 인물의 `career_paths`는 비워 두지 않는다. 경로를 알 수 없으면 `etc` + `path_detail`에 상황을 적는다 (예: `엑시트 직후`).

## 관리 규칙
- 태그를 **추가·이름 변경·폐기**하면 이 문서의 해당 표와 맨 아래 "변경 기록"을 함께 고치고, 기존 데이터도 새 태그로 바꾼다.
- 폐기한 태그는 지우지 않고 "폐기된 태그" 표로 옮긴다 (언제, 왜, 무엇으로 바꿨는지 남긴다).
- 표 첫 칸의 `code`가 데이터에 저장되는 값 그대로다. 한 번 정한 code는 되도록 바꾸지 않는다 (이름 변경은 한글 이름만).

| `future_plan` | 앞으로 계획 | topic | **미래** 계획, 목표, 꿈 | 이미 시작해서 하고 있는 일 (→ `current_status`) | "군대를 다녀온 뒤에는 제 사업을 해 보고 싶어요." | 2026-11-09 |
| `values` | 가치관 | topic | 삶의 키워드, 중요하게 여기는 가치, 삶을 대하는 태도·철학 | 진로를 고른 이유로 말할 때 (→ `choice_reason`), 후배에게 권하는 말 (→ `advice`) | "저는 후회하지 않는 걸 가장 중요하게 생각해요." | 2026-11-09 |
| `etc` | 기타 | topic | 위 어디에도 맞지 않을 때. `topic_detail`에 주제를 적는다 | 위 태그 중 하나라도 맞을 때 | — | 2026-11-09 |

경계 정리
- `campus_experience`(재학 중에 한 일) ↔ `what_helped`(졸업 후 실제로 도움이 된 것): 재학 중 경험이 졸업 후에 어떻게 쓰였는지까지 말하면 **둘 다** 붙인다.
- `current_status`(지금) ↔ `future_plan`(앞으로): 지금 하는 일과 앞으로의 계획을 같이 말하면 둘 다 붙인다.
