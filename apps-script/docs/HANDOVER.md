# 메일 자동화 인수인계 안내 (기관 담당자용)

꾸로록 사이트의 "멘토에게 문의하기" 메일 자동화를 기관 계정으로 옮겨 운영하는 방법입니다.
개발자가 아니어도 순서대로 따라 하면 됩니다. 코드는 고치지 않습니다.

```
학생(사이트 폼) → 사이트 서버 → [이 시트에 붙은 스크립트] → 기관 Gmail → 멘토
멘토 '답장' → 기관 Gmail → (5분마다 자동 확인) → 학생에게 전달 + 시트에 기록
```

## 준비물
- 기관용 **새 Gmail 계정** 1개 (메일을 보내고 받는 "중계 계정"이 됩니다. 예: `YOUR_RELAY_ACCOUNT@gmail.com`)
- 꾸로록 팀에게 받은 **템플릿 시트** 공유 링크
- 사이트(서버) 담당자 연락처 (웹앱 주소와 키를 전달해야 합니다)

> **가장 중요한 규칙**: 아래 모든 작업은 **중계 계정으로 로그인한 상태**에서 합니다.
> 다른 계정으로 메뉴를 누르거나 배포하면, 그 계정의 메일함에서 멘토에게 메일이 나갑니다.
> 크롬을 쓴다면 중계 계정 전용 프로필을 따로 만들어 쓰는 것을 권장합니다.

---

## 1단계. 템플릿 시트 사본 만들기
1. 중계 계정으로 로그인한 뒤 템플릿 시트 링크를 엽니다.
2. 메뉴 **파일 → 사본 만들기** → 이름을 `꾸로록 메일 자동화`로 정하고 **사본 만들기**.
   - 시트에 붙은 스크립트(코드)도 함께 복사됩니다.
3. 새로 열린 사본에서 작업합니다. (템플릿 원본은 더 쓰지 않습니다)

## 2단계. setup 실행 (설치·점검)
1. 사본을 새로고침하면 위쪽 메뉴에 **꾸로록 메일 자동화** 가 생깁니다. (안 보이면 10초 정도 기다린 뒤 새로고침)
2. **꾸로록 메일 자동화 → ① 설치·점검 (setup)** 을 누릅니다.
3. 처음에는 **승인 필요** 창이 뜹니다.
   1. **계속** → 중계 계정 선택
   2. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (안전하지 않음)으로 이동**
   3. 권한 목록을 확인하고 **허용**
   - 기관이 직접 만든 스크립트가 아니라 구글 심사를 받지 않아 나오는 화면입니다. 시트·Gmail을 이 스크립트가 쓰도록 허락하는 것입니다.
4. 승인 후 메뉴를 **한 번 더** 누르면 결과 창이 뜹니다. 아래가 보이면 성공입니다.
   - `실행 계정(중계 메일): (중계 계정 주소)` ← 주소가 중계 계정이 맞는지 꼭 확인
   - `탭·헤더 점검 완료`
   - `API_KEY·ADMIN_TOKEN: 준비됨`
   - `5분마다 checkReplies를 실행하는 트리거를 만들었습니다`
   - `⚠ 예시 메일(example.com)이 남은 멘토 …` ← 4단계에서 해결합니다
5. `⚠ 계정이 바뀌어 … 새로 만듭니다` 문구가 보여도 정상입니다. 꾸로록 팀이 쓰던 키를 지우고 기관 전용 키를 새로 만든 것입니다.

## 3단계. 웹앱 배포
웹앱 = 사이트 서버가 이 스크립트를 부를 수 있게 해 주는 인터넷 주소입니다.

1. 메뉴 **확장 프로그램 → Apps Script** (편집기가 새 탭으로 열립니다)
2. 오른쪽 위 **배포 → 새 배포**
3. ⚙(유형 선택) → **웹 앱**
4. 설명: `운영 v1`
   - **다음 사용자 인증 정보로 실행: 나(중계 계정)**
   - **액세스 권한이 있는 사용자: 모든 사용자**
5. **배포** → **웹 앱 URL**을 복사해 둡니다.
6. 편집기 왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성**에서 `API_KEY` 값을 복사해 둡니다.

> "모든 사용자"로 열어도 `API_KEY`가 없으면 아무것도 할 수 없습니다.
> 웹 앱 URL과 `API_KEY`는 비밀번호처럼 다룹니다. 공개 게시판·단체 채팅방에 올리지 않습니다.

## 4단계. 사이트 서버에 주소와 키 넣기
사이트 서버 담당자에게 아래 두 값을 **안전한 방법**(직접 전달, 비밀번호 관리 도구 등)으로 전달합니다.

| 전달할 값 | 어디서 찾나요 |
|---|---|
| 웹 앱 URL | 3단계 5번 |
| API_KEY | 3단계 6번 |

서버 담당자는 서버 환경변수의 기존 값을 이 두 값으로 **바꿔 넣고** 서버를 다시 시작합니다. (환경변수 이름은 서버 담당자가 알고 있습니다)
`ADMIN_TOKEN`은 관리자 페이지를 만들 때 필요합니다. 그때 같은 방법으로 전달합니다.

## 5단계. 멘토 등록
1. 시트의 **멘토** 탭을 엽니다.
2. 예시 줄(`mentor1@example.com` 등)을 실제 멘토로 바꿉니다.

| 열 | 적는 값 |
|---|---|
| mentorId | **사이트의 멘토 ID와 글자 하나까지 똑같이** (사이트 담당자에게 확인). 한 번 정하면 바꾸지 않습니다 |
| 이름 | 학생에게 보이는 이름 |
| 이메일 | 멘토가 평소 쓰는 메일 (Gmail이 아니어도 됩니다). **멘토가 답장을 보낼 주소와 같아야** 학생에게 전달됩니다 |
| 활성여부 | 체크하면 학생이 문의할 수 있습니다. 쉬는 멘토는 체크를 끕니다 (줄을 지우지 않습니다) |

3. 참여에 동의한 멘토만 넣습니다.
4. 다 넣었으면 **메뉴 → ① 설치·점검 (setup)** 을 한 번 더 눌러 `⚠ 예시 메일` 경고가 사라졌는지 확인합니다.

## 6단계. 동작 확인
1. **메뉴 → 상태 보기**: `API_KEY: 있음`, `답장 자동 확인 트리거: 1개`, 활성 멘토 수가 맞는지 봅니다.
2. 테스트 문의를 1건 보냅니다. 학생 이름은 테스트용, 학생 메일은 **담당자 본인 메일**, 멘토는 테스트에 협조해 줄 1명으로 합니다.
   아래 중 **하나**를 고릅니다.
   - **방법 A. 꾸로록 사이트에서 보내기** (사이트 서버에 4단계 값이 들어간 뒤)
     학생이 보는 꾸로록 웹사이트에서 멘토를 고르고 "문의하기" 폼(이름, 메일, 제목, 내용, 개인정보 동의)을 채워 보냅니다.
     실제 학생과 똑같은 경로라서 가장 확실한 확인입니다.
   - **방법 B. 편집기에서 보내기** (사이트 연결 전이거나 사이트 쪽 문제를 빼고 확인하고 싶을 때)
     1. 편집기(확장 프로그램 → Apps Script) → **⚙ 프로젝트 설정 → 스크립트 속성 추가**:
        속성 `TEST_STUDENT_EMAIL`, 값 = 담당자 본인 메일 → **스크립트 속성 저장**
     2. 멘토 탭에서 협조해 줄 멘토가 **맨 위의 활성 멘토**인지 확인합니다. (테스트는 첫 번째 활성 멘토에게 보냅니다)
     3. 편집기 위쪽 함수 선택 칸에서 `testSubmitInquiry` → **▷ 실행** → 실행 로그에 `"ok": true`가 보이면 성공
     - 제목은 `테스트 문의입니다`로 보내집니다.
3. 확인할 것
   - 시트 **문의** 탭에 한 줄이 생겼는지
   - 멘토가 `[꾸로록 문의] 제목` 메일을 받았는지 (스팸함도 확인), 보낸 사람 이름이 `꾸로록`인지
4. 멘토에게 받은 메일에서 **답장** 버튼으로 회신해 달라고 부탁합니다.
5. 5분 정도 기다리거나 **메뉴 → 답장 지금 확인**을 누릅니다.
6. 확인할 것
   - 담당자 메일함에 `[꾸로록 답장] 제목` 메일이 왔는지, 멘토가 쓴 내용만 있는지
   - **문의** 탭의 그 줄이 `답장여부 TRUE`, `답장일시`가 채워졌는지
7. 테스트 줄은 지우지 않아도 됩니다. 지우고 싶으면 그 줄 전체를 삭제합니다.

여기까지 되면 인수인계가 끝났습니다.

## 평소 운영

### 기록 보기
- **문의** 탭에서 모든 문의, 답장 여부, 답장 일시를 봅니다. 이 탭은 **직접 고치지 않습니다**. (행 순서 바꾸기·정렬 금지. 보기만 하려면 "필터 보기"를 쓰세요)
- 시트 공유는 **담당자까지만** 합니다. 학생 이름·메일(개인정보)이 들어 있습니다. "링크가 있는 모든 사용자" 공유는 쓰지 않습니다.

### 문구 바꾸기
- **설정** 탭의 `값` 열만 고칩니다. `키` 열은 바꾸지 않습니다. 바로 다음 메일부터 적용됩니다.

| 키 | 하는 일 |
|---|---|
| serviceName | 서비스 이름 |
| senderName | 메일 '보낸 사람'에 보이는 이름 |
| mentorSubjectPrefix | 멘토에게 가는 메일 제목 앞 말머리 |
| mentorFooter | 멘토에게 가는 메일 맨 아래 안내 문구 |
| studentSubjectPrefix | 학생에게 전달되는 답장 메일 제목 앞 말머리 |
| studentForwardIntro | 학생에게 전달되는 메일 맨 위 문구 |
| studentForwardFooter | 학생에게 전달되는 메일 맨 아래 문구 |

### 멘토 추가·중지
- 추가: **멘토** 탭 맨 아래에 줄을 추가합니다. (사이트에도 같은 mentorId로 등록되어 있어야 합니다)
- 중지: `활성여부` 체크를 끕니다. 이미 받은 문의에 대한 그 멘토의 답장은 계속 전달됩니다.

### 중계 메일함 라벨
| 라벨 | 뜻 | 할 일 |
|---|---|---|
| 메일자동화/전달완료 | 학생에게 전달함 | 없음 |
| 메일자동화/확인필요 | 등록되지 않은 주소에서 온 답장, 전달할 내용이 비어 있음, 발송 실패 중 하나 | 메일을 열어 확인하고 필요하면 담당자가 학생에게 직접 전달합니다. 멘토가 다른 주소로 답장했다면 멘토 탭 메일을 고친 뒤 멘토에게 다시 답장을 부탁합니다 |

- 멘토 답장이 **스팸함**에 들어가면 처리되지 않습니다. 가끔 스팸함을 확인하고, 멘토 메일이 있으면 "스팸 아님"으로 옮깁니다.
- 중계 메일함의 메일을 열어 봐도(읽음 처리) 괜찮습니다. 자동 전달에는 영향이 없습니다.

### 문제가 생겼을 때
| 증상 | 확인할 것 |
|---|---|
| 답장이 학생에게 안 감 | 메뉴 → 상태 보기에서 트리거가 1개인지. 0개면 "답장 자동 확인 켜기". 멘토가 '답장' 버튼으로 보냈는지(새 메일로 보내면 매칭되지 않음), 스팸함, 확인필요 라벨 |
| 사이트에서 문의가 안 보내짐 | 사이트 서버의 웹 앱 URL·API_KEY가 맞는지. 메뉴 → 상태 보기의 "오늘 남은 Gmail 발송 수"가 0인지 |
| 오류 원인을 자세히 보고 싶음 | 편집기(확장 프로그램 → Apps Script) 왼쪽 **☰ 실행** 메뉴에서 실행 기록과 로그 확인 |
| 트리거 실패 알림 메일이 옴 | 위 실행 기록에서 오류 내용을 확인. 탭 이름·헤더를 바꿨다면 원래대로 돌리고 setup 실행 |

### 키 바꾸기 (유출이 의심될 때)
1. 편집기 → **⚙ 프로젝트 설정 → 스크립트 속성**에서 `API_KEY`(또는 `ADMIN_TOKEN`) 줄을 삭제합니다.
2. 시트 **메뉴 → ① 설치·점검 (setup)** → 새 값이 만들어집니다.
3. 새 값을 사이트 서버 담당자에게 전달합니다. 서버에 넣기 전까지 사이트의 문의 보내기는 멈춥니다.

### 코드가 바뀌었을 때 (꾸로록 팀·개발자에게 받은 경우)
1. 편집기에서 바뀐 파일 내용을 붙여넣고 저장합니다.
2. **배포 → 배포 관리 → ✏(수정) → 버전: 새 버전 → 배포**. ("새 배포"를 누르면 주소가 바뀌니 주의)
3. 시트 메뉴 → setup을 한 번 실행합니다.

## 알아 둘 한계
- Gmail로 메일을 보내기 때문에 **하루 약 100통**까지만 보낼 수 있고(문의 + 답장 전달 합계), 스팸함에 들어갈 수 있습니다.
- 정식 운영 규모가 커지면 **기관 도메인 + 메일 발송 전문 서비스**로 바꾸는 것을 권장합니다. 코드에서 보내기(`Mailer.gs`)·받기(`Receiver.gs`)가 따로 나뉘어 있어서 그 부분만 바꾸면 됩니다. (개발자 작업 필요)
- 멘토는 반드시 받은 메일의 **'답장' 버튼**으로 회신해야 합니다.
- 학생이 전달받은 메일에 다시 답장하는 것(2차 왕복)과 첨부파일·이미지는 지원하지 않습니다. 답장은 글자만 전달됩니다.
- 멘토가 답장 본문에 직접 쓴 서명·전화번호는 학생에게 그대로 전달됩니다. 멘토에게 미리 안내해 주세요.
