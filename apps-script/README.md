# 꾸로록 메일 자동화 (Google Apps Script)

학생이 멘토에게 보낸 문의를 **중계 Gmail 계정**을 거쳐 멘토에게 보내고,
멘토가 '답장'하면 그 답장을 학생에게 자동으로 전달하는 기능입니다.
모든 기록은 **구글 시트**에 남습니다.

```
학생(사이트 폼) → 팀 백엔드 서버 → Apps Script 웹앱 → 중계 Gmail → 멘토
멘토 '답장' → 중계 Gmail 받은편지함 → (5분마다 자동 확인) → 학생에게 전달 + 시트 기록
```

> 이 문서는 **꾸로록 팀(개발·운영)** 용입니다. 개발자가 아니어도 따라 할 수 있게 쓰였습니다.
> 지금은 **Step 6(인수인계 패키지)** 와 **Step 5-1(학생 사본·멘토 리마인드·횟수 제한)** 까지의 내용이 있습니다.
> 관리자 API(Step 5-2)는 팀이 관리자 페이지를 만들 때 추가합니다.
>
> **기관(거꾸로캠퍼스) 담당자는 [docs/HANDOVER.md](./docs/HANDOVER.md)만 보면 됩니다.**

---

## 0. 꼭 지켜야 할 규칙

1. **모든 작업은 중계 계정(팀 공용 구글 계정)으로 로그인한 상태에서** 합니다.
   - Apps Script에서 함수를 실행하거나 트리거를 만들면, **그 버튼을 누른 사람의 계정**으로 메일이 나갑니다.
   - 팀원 개인 계정으로 실행하면 개인 Gmail에서 멘토에게 메일이 나가 버립니다.
   - 팀원 개인 계정은 **시트 기록을 보는 용도**로만 씁니다.
2. 이 저장소는 공개(public)입니다. 아래 값은 **코드·문서·커밋 메시지에 절대 적지 않습니다.**
   - apiKey, adminToken, 이메일 주소(중계 계정·멘토·학생), 시트 ID, 스크립트 ID, 웹앱 배포 URL
   - 문서에는 `YOUR_API_KEY`, `YOUR_SCRIPT_ID` 같은 자리표시자만 씁니다.
3. 시트에는 학생 이름·메일(개인정보)이 쌓입니다. 시트 공유는 **팀원까지만**, "링크가 있는 모든 사용자" 공유는 쓰지 않습니다.

## 1. 폴더 구조

```
apps-script/
├── README.md              ← 지금 이 문서 (세팅·인수인계 안내)
├── .gitignore             ← 비밀 파일이 올라가지 않게 막는 목록
├── .clasp.json.example    ← (나중에) clasp 연결 설정 예시. 실제 파일 .clasp.json 은 올리지 않음
├── src/                   ← Apps Script 에 들어가는 코드 (파일 이름 그대로 편집기에 만듦)
│   ├── appsscript.json    ← 프로젝트 설정(시간대 = 한국, 웹앱 설정)
│   ├── Main.gs            ← 웹앱 입구. 요청을 받아 action별로 나눔
│   ├── Config.gs          ← 탭·헤더 이름, 길이 제한, 비밀값 읽기, initSecrets()
│   ├── Response.gs        ← 공통 응답 형식과 에러 코드
│   ├── Sheets.gs          ← 시트 읽기 도구, "설정" 탭 읽기
│   ├── Mentors.gs         ← getMentors (활성 멘토 목록, 이메일 제외)
│   ├── Inquiries.gs       ← submitInquiry (검사 → 저장 → 발송)
│   ├── MailTemplates.gs   ← 멘토에게 갈 메일 내용 만들기
│   ├── Mailer.gs          ← 실제 발송 (나중에 발송 전문 서비스로 바꿀 때 이 파일만 교체)
│   ├── Receiver.gs        ← 받은 메일 읽기 (나중에 바꿀 때 이 파일만 교체)
│   ├── ReplyParser.gs     ← 답장에서 문의번호 찾기, 인용문·안내 문구 지우기
│   ├── Replies.gs         ← checkReplies: 답장을 학생에게 전달 + 시트 기록
│   ├── Reminders.gs       ← sendReminders: 답장 없는 문의를 10일째 멘토에게 한 번 더 보내기
│   ├── Triggers.gs        ← 자동 실행 트리거 켜기/끄기 (답장 확인 5분마다, 리마인드 매일)
│   ├── Setup.gs           ← setup(): 설치·점검 한 번에, clearForTemplate(): 템플릿 사본 비우기
│   ├── Menu.gs            ← 시트 위쪽 "꾸로록 메일 자동화" 메뉴
│   └── Test.gs            ← 편집기에서 실행하는 테스트
├── docs/
│   ├── API.md             ← 팀 백엔드가 호출하는 API 명세
│   └── HANDOVER.md        ← 기관 담당자용 인수인계·운영 안내
└── templates/             ← 시트 탭 3개의 틀 (CSV). 테스트용 가짜 값만 들어 있음
    ├── mentors.example.csv    → "멘토" 탭
    ├── inquiries.example.csv  → "문의" 탭 (헤더만)
    └── settings.example.csv   → "설정" 탭
```

- 용어 풀이
  - **Apps Script**: 구글 시트·Gmail을 자동으로 다루는 구글의 무료 코드 실행 도구.
  - **바인딩된 스크립트**: 특정 시트 안에 붙어 있는 스크립트. 시트를 '사본 만들기'하면 스크립트도 같이 복사됩니다.
  - **clasp**: 내 컴퓨터의 코드 파일을 Apps Script로 올리고 내려받는 명령어 도구. (나중에 도입)

## 2. 시트 만들기 (Step 2)

### 2-1. 새 시트 만들기
1. 중계 계정으로 로그인한 뒤 [Google Sheets](https://sheets.google.com)에서 **빈 스프레드시트**를 만듭니다.
2. 왼쪽 위 제목을 `꾸로록 메일 자동화`로 바꿉니다.

### 2-2. 탭 3개 가져오기 (CSV 파일 이용)
`templates/` 폴더의 CSV 파일 3개를 내 컴퓨터에 내려받은 뒤, 파일마다 아래를 반복합니다.

1. 시트 메뉴 **파일 → 가져오기 → 업로드** 에서 CSV 파일을 선택합니다.
2. "위치 가져오기"는 **새 시트 삽입**, "구분자 유형"은 **자동 감지**를 고르고 **데이터 가져오기**를 누릅니다.
3. 아래쪽에 새로 생긴 탭 이름을 더블클릭해 바꿉니다.

| CSV 파일 | 탭 이름 (정확히 이대로) |
|---|---|
| mentors.example.csv | `멘토` |
| inquiries.example.csv | `문의` |
| settings.example.csv | `설정` |

4. 처음부터 있던 빈 탭 `시트1`은 지웁니다 (탭 이름 우클릭 → 삭제).

> 탭 이름과 1행(헤더) 글자는 코드가 그대로 찾습니다. 띄어쓰기 하나라도 다르면 동작하지 않습니다.

### 2-3. 각 탭 확인·정리

**멘토 탭** — 열: `mentorId | 이름 | 이메일 | 활성여부`
1. 테스트용 가짜 값(`mentor1@example.com` 등)을 **팀원 6명의 실제 메일**로 바꿉니다. (이 값은 시트에만 적고, GitHub·채팅에는 적지 않습니다.)
2. `이름`은 학생에게 보이는 이름입니다.
3. `활성여부` 열(D열)을 선택 → 메뉴 **삽입 → 체크박스**. 체크된 멘토만 학생에게 보이고 문의를 받습니다.
4. `mentorId`는 한 번 정하면 바꾸지 않습니다 (문의 기록이 이 값으로 멘토를 찾습니다).
   - **사이트(팀 백엔드)의 멘토 ID와 글자 하나까지 똑같이** 적습니다. 학생이 사이트에서 고른 멘토 ID로 이 탭에서 메일 주소를 찾기 때문입니다.
   - 지금 견본은 백엔드 데모 데이터와 같은 `mt-01` ~ `mt-06` 형식입니다. 새 멘토는 `mt-07`처럼 이어서 붙입니다.
   - 코드는 ID 형식을 따지지 않고 그냥 글자(문자열)로 비교합니다. 다만 앞뒤 공백, 대소문자가 다르면 다른 ID로 봅니다.

**문의 탭** — 열: `문의번호 | 보낸일시 | mentorId | 학생이름 | 학생메일 | 제목 | 내용 | 답장여부 | 답장일시 | 리마인드일시`
(`리마인드일시`는 Step 5-1에서 추가. 이미 쓰던 시트는 setup이 오른쪽 끝에 자동으로 붙입니다)
1. 1행 헤더만 있으면 됩니다. 2행부터는 코드가 자동으로 채웁니다. **직접 입력하거나 행 순서를 바꾸지 않습니다.**
2. A열(문의번호), B열(보낸일시), I열(답장일시)을 선택 → 메뉴 **서식 → 숫자 → 일반 텍스트**.
   (시트가 날짜·숫자를 멋대로 바꾸지 않게 하기 위해서입니다.)

**설정 탭** — 열: `키 | 값 | 설명`
1. 코드는 `키` 열로 값을 찾습니다. **`키` 열은 바꾸지 말고, `값` 열만 수정**합니다.
2. 기관에 넘길 때는 서비스 이름·보낸 사람 이름·안내 문구를 여기서만 바꾸면 됩니다.

| 키 | 하는 일 |
|---|---|
| serviceName | 서비스 이름 |
| senderName | 메일 '보낸 사람'에 보이는 이름 |
| mentorSubjectPrefix | 멘토에게 가는 메일 제목 앞 말머리 |
| mentorFooter | 멘토에게 가는 메일 맨 아래 안내 문구 |
| studentSubjectPrefix | 학생에게 전달되는 답장 메일 제목 앞 말머리 |
| studentForwardIntro | 학생에게 전달되는 메일 맨 위 문구 |
| studentForwardFooter | 학생에게 전달되는 메일 맨 아래 문구 |
| rateLimitMinutes | (5-1) 같은 학생 메일의 문의 수를 셀 시간(분). 기본 10, 0이면 이 제한 없음 |
| rateLimitPerWindow | (5-1) rateLimitMinutes분 안에 같은 학생 메일로 보낼 수 있는 수. 기본 3, 0이면 이 제한 없음 |
| rateLimitPerDay | (5-1) 같은 학생 메일로 하루(자정 기준) 보낼 수 있는 수. 기본 5, 0이면 제한 없음 |
| studentCopySubjectPrefix | (5-1) 학생에게 가는 "보낸 문의 사본" 제목 앞 말머리 |
| studentCopyIntro | (5-1) 사본 메일 맨 위 문구 |
| studentCopyFooter | (5-1) 사본 메일 맨 아래 문구 |
| reminderDays | (5-1) 보낸 날짜로부터 며칠째에 리마인드를 보낼지. 기본 10, 0이면 보내지 않음 |
| mentorReminderSubjectPrefix | (5-1) 리마인드 메일 제목 앞 말머리 |
| mentorReminderIntro | (5-1) 리마인드 메일 맨 위 문구 |

> 숫자 키(rateLimitMinutes, rateLimitPerWindow, rateLimitPerDay, reminderDays)가 비어 있거나 숫자가 아니면 기본값을 씁니다.
>
> **테스트 기간에는 횟수 제한을 꺼 둡니다**: `rateLimitMinutes`와 `rateLimitPerDay`를 `0`으로 둡니다.
> **템플릿을 만들기 전과 실제 운영 전에는 반드시 `10`과 `5`로 되돌립니다.** (원본 설정 탭 값이 템플릿에 그대로 복사됩니다)

> 중계 메일 주소는 설정 탭에 적지 않습니다. 코드가 "지금 스크립트를 배포한 계정"의 주소를 자동으로 씁니다.
> 그래서 기관이 새 Gmail 계정으로 시트 사본을 만들면, 주소를 따로 바꿀 필요가 없습니다.

## 3. 시트에 Apps Script 붙이기 (Step 2)

1. 시트 메뉴 **확장 프로그램 → Apps Script** 를 누릅니다. (반드시 시트 안에서 열어야 '바인딩된 스크립트'가 됩니다.)
2. 왼쪽 위 프로젝트 이름 `제목 없는 프로젝트`를 `꾸로록 메일 자동화`로 바꿉니다.
3. 왼쪽 **⚙ 프로젝트 설정** → **"편집기에 'appsscript.json' 매니페스트 파일 표시"** 를 체크합니다.
4. 같은 화면의 **시간대**가 `(GMT+09:00) 서울`인지 확인합니다.
5. 왼쪽 **< > 편집기**로 돌아가 `appsscript.json` 파일을 열고, 내용을 전부 지운 뒤 `src/appsscript.json` 내용을 붙여넣고 저장(Ctrl+S)합니다.
6. 기본으로 있는 `Code.gs`는 그대로 둡니다 (Step 3에서 `Main`으로 이름을 바꿉니다).

## 4. 팀원 초대 (Step 2)

1. 시트 오른쪽 위 **공유** → 팀원 개인 구글 계정을 **편집자**로 추가합니다.
   - 시트 편집자는 바인딩된 Apps Script도 자동으로 편집할 수 있습니다.
2. "일반 액세스"가 **제한됨**인지 확인합니다 ("링크가 있는 모든 사용자"로 두지 않습니다).
3. 팀원에게 **0번 규칙**(실행·배포는 중계 계정으로만)을 꼭 알려 줍니다.

## 5. 코드 보관 방식 (GitHub)

- 코드의 원본은 이 저장소의 `apps-script/src/` 입니다.
- 지금은 **GitHub 파일 내용을 복사해 Apps Script 편집기에 붙여넣는 방식**으로 진행합니다.
  - Apps Script에서 고친 내용이 있으면 반드시 `src/`의 같은 파일에도 반영해 커밋합니다.
  - Apps Script의 `Code.gs` ↔ GitHub의 `src/Code.gs`처럼 파일 이름을 똑같이 맞춥니다.
- 동작 확인 후 clasp를 도입하면 `.clasp.json.example`을 복사해 `.clasp.json`을 만들고,
  `YOUR_SCRIPT_ID` 자리에 실제 스크립트 ID를 넣습니다. (`.clasp.json`은 .gitignore에 있어 올라가지 않습니다.)
- 웹앱 배포는 **배포 담당자 1명**만 합니다.

## 6. 코드 붙여넣기와 웹앱 배포 (Step 3)

### 6-1. 코드 파일 붙여넣기
1. Apps Script 편집기에서 `Code.gs` 이름 옆 ⋮ → **이름 바꾸기** → `Main` (자동으로 `Main.gs`가 됩니다).
2. `Main.gs` 내용을 전부 지우고 `src/Main.gs` 내용을 붙여넣습니다.
3. 나머지 파일은 왼쪽 **파일 옆 +** → **스크립트** → 이름 입력(`.gs`는 빼고) → 내용 붙여넣기를 반복합니다.
   - `Config`, `Response`, `Sheets`, `Mentors`, `Inquiries`, `MailTemplates`, `Mailer`, `Test`
   - (Step 4) `Receiver`, `ReplyParser`, `Replies`, `Triggers`
4. 모두 붙여넣고 저장(Ctrl+S)합니다. 파일 순서는 상관없습니다.

### 6-2. 비밀값 만들기 (처음 한 번)
> Step 6부터는 시트 메뉴의 **① 설치·점검 (setup)** 이 이 과정(비밀값·트리거·탭 점검)을 한 번에 해 줍니다. 아래는 개별 함수로 하는 방법입니다.

1. 위쪽 함수 선택 칸에서 `initSecrets` → **▷ 실행**.
2. 처음 실행하면 **권한 검토** 창이 뜹니다. 중계 계정을 고르고 → "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (안전하지 않음)으로 이동** → **허용**.
   (우리 팀이 만든 스크립트라 구글 심사를 받지 않아 나오는 화면입니다. 시트·Gmail 권한을 이 스크립트에 주는 것입니다.)
3. 실행 로그에 `API_KEY: 새로 만들어 저장했습니다`와 중계 메일 주소가 보이면 성공입니다.
4. **⚙ 프로젝트 설정 → 스크립트 속성**에서 `API_KEY`, `ADMIN_TOKEN` 값이 생긴 것을 확인합니다.
   - 이 값은 팀 백엔드 서버의 환경변수에만 넣습니다. GitHub·채팅·문서에 적지 않습니다.
   - 다시 실행해도 이미 있는 값은 바꾸지 않습니다. 키를 바꾸고 싶으면 스크립트 속성에서 지우고 다시 실행합니다.
5. 같은 화면에서 **스크립트 속성 추가** → 속성 `TEST_STUDENT_EMAIL`, 값 = 테스트 답장을 받을 내 메일 → 저장.

### 6-3. 편집기에서 테스트하기 (배포 전)
함수 선택 칸에서 고르고 **▷ 실행** → 아래 실행 로그를 봅니다.

| 함수 | 확인하는 것 | 메일 발송 |
|---|---|---|
| `testGetMentors` | 활성 멘토만 나오는지, 응답에 이메일이 없는지 | 없음 |
| `testValidationErrors` | 잘못된 입력 10가지가 맞는 에러 코드를 내는지 (모두 ✅) | 없음 |
| `testSubmitInquiry` | "문의" 탭에 한 줄이 생기고, 첫 번째 활성 멘토에게 메일이 가는지 | 1통 |

`testSubmitInquiry` 뒤에 멘토 메일함에서 확인할 것:
- 보낸 사람 이름이 설정 탭 `senderName`(예: 꾸로록)인지
- 제목이 `[꾸로록 문의] 제목` 모양인지 (문의번호는 제목에 없습니다)
- 맨 아래에 안내 문구가 있고, 그 아래 작은 글씨로 `문의번호: q날짜-0001` 한 줄이 있는지
- **답장** 버튼을 누르면 받는 사람이 `중계계정+문의번호@...` 로 채워지는지 (실제로 보내지는 않아도 됩니다. 답장 처리는 Step 4)

### 6-4. 웹앱 배포 (배포 담당자 1명)
1. 오른쪽 위 **배포 → 새 배포**.
2. ⚙(유형 선택) → **웹 앱**.
3. 설명: `v1 문의 발송` 처럼 적습니다.
4. **다음 사용자 인증 정보로 실행: 나(중계 계정)**, **액세스 권한이 있는 사용자: 모든 사용자**.
5. **배포** → 나오는 **웹 앱 URL**을 복사합니다.
   - 이 URL도 GitHub·문서에 적지 않고, 팀 백엔드 서버의 환경변수에만 넣습니다.

> "모든 사용자"로 열어도 apiKey가 없으면 아무것도 할 수 없습니다.

### 6-5. 코드를 고친 뒤 다시 배포하기 (URL 유지)
1. **배포 → 배포 관리** → 기존 배포 선택 → ✏(수정).
2. **버전: 새 버전** → **배포**.
   - "새 배포"를 다시 누르면 URL이 바뀝니다. 꼭 "배포 관리"에서 수정합니다.
   - 저장만 하고 새 버전을 배포하지 않으면 웹앱에는 반영되지 않습니다.

### 6-6. 배포된 웹앱 테스트 (Postman)
1. Postman에서 **New → HTTP**, 방식 **POST**, 주소에 웹 앱 URL.
2. **Body → raw → Text** 를 고르고 아래를 붙여넣습니다 (`YOUR_API_KEY`만 실제 값으로).
   ```json
   { "apiKey": "YOUR_API_KEY", "action": "getMentors" }
   ```
3. **Send** → `{"ok":true,"data":{"mentors":[...]}}` 가 오면 성공입니다.
4. 문의 제출은 아래처럼 보냅니다 (메일 1통 사용).
   ```json
   { "apiKey": "YOUR_API_KEY", "action": "submitInquiry", "mentorId": "mt-01",
     "studentName": "테스트학생", "studentEmail": "YOUR_TEST_EMAIL",
     "title": "Postman 테스트", "body": "테스트 내용입니다.", "privacyConsent": true }
   ```

> 웹앱은 응답 전에 다른 주소로 한 번 넘겨줍니다(리다이렉트). Postman은 자동으로 따라가지만,
> 터미널 curl을 쓸 때는 `-L` 옵션이 꼭 필요합니다.

## 7. 답장 자동 전달 (Step 4)

### 7-1. 어떻게 동작하나요?
5분마다 `checkReplies`가 중계 Gmail을 확인합니다.

1. 문의번호를 찾습니다.
   - 1순위: 답장을 받은 주소의 `+문의번호` (멘토가 '답장' 버튼을 누르면 자동으로 채워짐)
   - 2순위: 답장 아래 인용된 원래 메일의 `문의번호: q...` 줄
   - 둘 다 없거나 시트에 없는 번호면 **무시**합니다. (일반 메일은 건드리지 않음)
2. 보낸 사람이 **그 문의의 멘토(멘토 탭에 등록된 메일)** 인지 확인합니다. 다르면 전달하지 않고 `메일자동화/확인필요` 라벨을 붙입니다.
3. 인용된 원래 메일, `문의번호` 줄, 멘토 안내 문구를 지우고 **멘토가 쓴 부분만** 학생에게 보냅니다. 학생 메일에는 멘토 **이름만** 보이고 멘토 메일 주소는 보이지 않습니다.
4. "문의" 탭에 `답장여부 = TRUE`, `답장일시 = 첫 답장 시각`을 기록하고 `메일자동화/전달완료` 라벨을 붙입니다.
   - 멘토가 여러 번 답장하면 **모두 전달**하고, 답장일시는 **첫 답장 시각 그대로** 둡니다.

> 처리한 메일은 스크립트가 따로 기억합니다. 사람이 중계 메일함에서 메일을 열어 봐도(읽음 처리) 괜찮습니다.
> 스크립트 속성의 `REPLY_LAST_CHECKED_AT`, `REPLY_PROCESSED_IDS`는 자동으로 관리되는 값이라 직접 고치지 않습니다.

### 7-2. 코드 붙여넣기
1. 6-1과 같은 방법으로 새 파일 4개를 만듭니다: `Receiver`, `ReplyParser`, `Replies`, `Triggers`.
2. 바뀐 파일 5개는 내용을 전부 지우고 새로 붙여넣습니다: `Config`, `Mentors`, `Mailer`, `MailTemplates`, `Test`.
3. 저장합니다.
4. 웹앱에도 바뀐 코드가 반영되도록 **6-5 방법(배포 관리 → 새 버전)** 으로 다시 배포합니다.

### 7-3. 편집기에서 테스트
1. `testReplyParser` 실행 → 모두 ✅ 인지 봅니다. (메일을 보내거나 읽지 않습니다)
2. 처음 실행하면 Gmail 권한을 다시 물을 수 있습니다. 중계 계정으로 **허용**합니다.

### 7-4. 트리거 켜기 (중계 계정으로)
1. `installReplyTrigger` 실행 → 로그에 "5분마다 checkReplies를 실행하는 트리거를 만들었습니다"와 중계 메일 주소가 보이면 성공.
2. 왼쪽 **⏰ 트리거** 메뉴에 `checkReplies` / 시간 기반 / 5분마다 가 1개 있는지 확인합니다.
   - 2개 이상이면 `installReplyTrigger`를 한 번 더 실행합니다 (기존 것을 지우고 1개만 만듭니다).
3. 끄고 싶으면 `removeReplyTrigger`를 실행합니다.

### 7-5. 실제 왕복 테스트
1. `testSubmitInquiry` 실행 → 첫 번째 활성 멘토(팀원)에게 문의 메일이 갑니다.
2. 그 팀원이 받은 메일에서 **답장** 버튼을 눌러 아무 내용이나 써서 보냅니다.
3. 5분 정도 기다리거나, 편집기에서 `checkReplies`를 직접 실행합니다.
4. 확인할 것
   - `TEST_STUDENT_EMAIL` 메일함에 `[꾸로록 답장] 테스트 문의입니다` 메일이 왔는지 (스팸함도 확인)
   - 학생 메일에 **멘토가 쓴 내용만** 있고, 원래 문의 내용·멘토 안내 문구·문의번호 줄·멘토 메일 주소가 **없는지**
   - "문의" 탭의 그 줄이 `답장여부 TRUE`, `답장일시`가 채워졌는지
   - 중계 메일함의 그 메일에 `메일자동화/전달완료` 라벨이 붙었는지
5. (선택) 같은 메일에 멘토가 한 번 더 답장 → 학생에게 또 전달되고, 답장일시는 그대로인지 확인합니다.
6. (선택) 다른 계정으로 `중계계정+문의번호@gmail.com`에 메일을 보내 봅니다 → 학생에게 전달되지 않고 `확인필요` 라벨이 붙어야 합니다.

### 7-6. '확인필요' 라벨이 붙었을 때
중계 메일함에서 `메일자동화/확인필요` 라벨을 눌러 봅니다. 원인은 셋 중 하나입니다.

| 원인 | 할 일 |
|---|---|
| 멘토가 등록되지 않은 다른 주소로 답장함 | 내용을 확인하고 담당자가 학생에게 직접 전달하거나, 멘토 탭의 메일을 맞게 고친 뒤 멘토에게 다시 답장을 부탁합니다 |
| 답장에서 전달할 내용을 찾지 못함 (멘토가 인용 부분 안에 답을 씀 등) | 내용을 확인하고 담당자가 직접 전달합니다 |
| 학생에게 보내기 실패 (일일 발송 한도 등) | 자동으로 다음 확인 때 다시 보냅니다. 계속 실패하면 실행 로그를 확인합니다 |

> 자세한 기록은 편집기 왼쪽 **☰ 실행** 메뉴에서 `checkReplies` 실행 로그로 볼 수 있습니다.

## 8. 인수인계 패키지 (Step 6)

### 8-1. setup()과 시트 메뉴
- 시트를 열면 위쪽에 **꾸로록 메일 자동화** 메뉴가 생깁니다 (`Menu.gs`의 `onOpen`).
- 메뉴를 누른 사람의 계정으로 실행됩니다. **중계 계정으로만** 누릅니다.

| 메뉴 | 하는 일 |
|---|---|
| ① 설치·점검 (setup) | 계정 확인 → 빠진 탭·헤더·설정 키만 만들기 → API_KEY·ADMIN_TOKEN 없으면 만들기 → 답장 확인·리마인드 트리거 각 1개 켜기 → 멘토 예시 메일 경고 |
| 상태 보기 | 키 유무, 트리거 개수, 마지막 답장 확인 시각, 멘토·문의 수, 남은 발송 수 |
| 답장 지금 확인 | `checkReplies` 바로 실행 |
| 리마인드 지금 보내기 | `sendReminders` 바로 실행 (조건에 맞는 문의만. Step 5-1) |
| 자동 실행 켜기/끄기 | 답장 확인(5분마다) + 리마인드(매일) 트리거를 둘 다 켜기/끄기 (`installAutoTriggers` / `removeAutoTriggers`) |
| 템플릿용으로 데이터 비우기 | 파일 이름에 "템플릿"이 있는 사본에서만, 확인 창 2번 후 실행 |

**setup()의 계정 확인 규칙** (Script Properties의 `SETUP_OWNER`로 판단)
- 처음 실행이고 API_KEY도 없음 → 새 설치. 키를 새로 만듭니다.
- 처음 실행인데 API_KEY는 있음 → setup 도입 전부터 쓰던 시트(지금 팀 시트). **키를 그대로 둡니다.**
- 이전 실행 계정과 지금 계정이 다름 → 사본을 다른 계정이 만든 것. API_KEY·ADMIN_TOKEN·답장 처리 기록·TEST_STUDENT_EMAIL을 지우고 새로 만듭니다.

### 8-2. 지금 팀 시트에 적용하기
1. 7-2처럼 새 파일 `Setup`, `Menu`를 만들고, 바뀐 파일 `Config`, `Triggers`, `Replies`를 새로 붙여넣고 저장합니다.
2. **배포 관리 → 새 버전**으로 다시 배포합니다.
3. 시트를 새로고침 → **꾸로록 메일 자동화 → ① 설치·점검 (setup)** (처음이면 권한 승인 후 한 번 더).
4. 결과 창에서 확인: 실행 계정이 중계 계정인지, `⚠ 계정이 바뀌어` 문구가 **없는지**(있으면 안 됨: 키가 바뀐 것), 트리거가 만들어졌는지.
5. **상태 보기**에서 `답장 자동 확인 트리거: 1개`(Step 5-1부터는 `리마인드 트리거: 1개`도), 문의 수가 맞는지 확인합니다.

### 8-3. 기관에 넘길 템플릿 시트 만들기 (팀 담당자)
1. 팀 시트 **설정** 탭의 횟수 제한이 켜져 있는지 확인합니다: `rateLimitMinutes`=`10`, `rateLimitPerWindow`=`3`, `rateLimitPerDay`=`5`. (테스트하느라 `0`으로 꺼 두었다면 먼저 되돌립니다. 사본에 그대로 복사됩니다)
2. 팀 시트에서 **파일 → 사본 만들기** → 이름: `꾸로록 메일 자동화 템플릿` (이름에 "템플릿" 필수).
3. 사본을 엽니다. (사본의 스크립트는 원본과 별개라, 사본에서 하는 일은 원본에 영향이 없습니다)
4. 사본에서 **꾸로록 메일 자동화 → 템플릿용으로 데이터 비우기** → 확인 → `비우기` 입력.
5. 확인할 것: 문의 탭은 헤더만, 멘토 탭은 `mentor1@example.com` 같은 예시 6줄, 설정 탭은 그대로.
6. 편집기 → ⚙ 프로젝트 설정 → 스크립트 속성이 **비어 있는지** 확인합니다.
7. 이 템플릿을 기관 계정에 **뷰어**로 공유합니다. 기관은 HANDOVER.md 1단계(사본 만들기)부터 진행합니다.

> 원본(팀 시트)은 기관에 공유하지 않습니다. 원본에는 팀원 메일과 테스트 문의 기록이 있습니다.

### 8-4. 인수인계 리허설 (교체 후 동작 검증)
실제로 넘기기 전에, 팀이 **다른 테스트용 Gmail 계정**으로 HANDOVER.md를 처음부터 끝까지 따라 해 봅니다.
1. 테스트 계정으로 템플릿 사본 만들기 → setup → 웹앱 배포 → 멘토 탭에 팀원 메일 1명 입력.
2. Postman(6-6)으로 **새 웹앱 URL + 새 API_KEY**로 `getMentors`, `submitInquiry` 호출.
3. 팀원이 '답장' → 테스트 학생 메일로 전달되는지, 시트 기록이 되는지 확인.
4. **이전(팀) 웹앱 URL과 API_KEY는 새 사본에서 통하지 않는지** 확인 (새 URL에 옛 키로 호출 → `UNAUTHORIZED`).
5. 확인이 끝나면 테스트 계정의 트리거를 끄고(메뉴 → 자동 실행 끄기) 테스트 사본을 지웁니다.

코드는 한 줄도 고치지 않고, 계정·시트 사본·멘토 탭만 바뀌어도 동작하는지 보는 것이 목적입니다.

## 9. 학생 사본·멘토 리마인드·횟수 제한 (Step 5-1)

### 9-1. 무엇이 바뀌나요?
| 기능 | 내용 |
|---|---|
| 횟수 제한 | 같은 학생 메일로 **최근 10분 안에 3건, 하루(자정 기준) 5건**까지. 넘으면 `TOO_MANY_REQUESTS` (학생에게 보여 줄 문구가 응답 `message`에 있음). 숫자는 설정 탭에서 바꾸고, 0이면 제한 없음 |
| 학생 사본 | 문의가 멘토에게 간 직후, 학생 메일로 "보낸 문의 사본" 1통 (멘토 이름·제목·내용·보낸 일시). 사본 발송이 실패해도 문의는 성공 처리 (로그만 남김). 학생이 사본에 답장해도 멘토에게 가지 않음 |
| 멘토 리마인드 | 답장 없는 문의는 **보낸 날짜 + 10일째** 오전 10~11시에 멘토에게 한 번 더 감. 제목 `[꾸로록 리마인드] 제목`, 맨 위 리마인드 문구. 한 문의에 한 번만. 멘토가 비활성이면 안 보냄. 리마인드 메일에 '답장'해도 학생에게 자동 전달 |
| 라벨 정리 | 전달 실패로 `확인필요`가 붙었던 메일이 다음 확인 때 전달되면 `확인필요`를 떼고 `전달완료`만 남김 |
| 안내 문구 | 비밀값이 없을 때 로그 안내가 "setup 실행"으로 바뀜 |

- 문의 1건에 Gmail 발송 2통(멘토 + 학생 사본)을 씁니다. 리마인드도 1통씩 씁니다. (하루 약 100통 한도 안에서 계산)
- 시트 메뉴가 바뀝니다: "답장 자동 확인 켜기/끄기" → **"자동 실행 켜기/끄기"**(답장 확인 + 리마인드), **"리마인드 지금 보내기"** 추가.

### 9-2. 코드 붙여넣기 (중계 계정으로, 순서대로)
1. 새 파일 1개를 만듭니다: `Reminders`.
2. 바뀐 파일 12개는 내용을 전부 지우고 새로 붙여넣습니다:
   `Config`, `Response`, `Sheets`, `Inquiries`, `MailTemplates`, `Receiver`, `ReplyParser`, `Replies`, `Triggers`, `Setup`, `Menu`, `Test`
   (`Main`, `Mentors`, `Mailer`는 그대로)
3. 저장(Ctrl+S)합니다.
4. **바로** 시트를 새로고침 → **꾸로록 메일 자동화 → ① 설치·점검 (setup)**.
   - 새 코드는 문의 탭의 `리마인드일시` 열이 있어야 동작합니다. setup이 이 열과 새 설정 키 9개를 자동으로 추가하고 리마인드 트리거를 켭니다.
   - setup 전에는 5분마다 도는 답장 확인이 실패해 중계 계정으로 오류 알림 메일이 올 수 있습니다. 저장 후 바로 setup하면 됩니다.
   - 결과 창에 `"설정" 탭에 빠진 키를 기본값으로 추가했습니다: rateLimitMinutes, …`, `"문의" 탭 1행에 빠진 헤더를 오른쪽 끝에 추가했습니다: 리마인드일시`, `매일 10시~11시 사이에 sendReminders를 실행하는 트리거를 만들었습니다`가 보이면 성공.
5. 아래 9-3 테스트를 한 뒤, 웹앱을 **배포 관리 → 새 버전**(6-5)으로 다시 배포합니다.

### 9-3. 테스트
| 함수 | 확인하는 것 | 메일 발송 |
|---|---|---|
| `testValidationErrors` | 기존 검사 10가지 (모두 ✅) | 없음 |
| `testReplyParser` | 기존 + 리마인드 메일에 답장한 경우 2가지 (모두 ✅) | 없음 |
| `testRateLimit` | 10분 3건·하루 5건 계산과 안내 문구 14가지 (모두 ✅). 설정 탭 값과 상관없이 검사 | 없음 |
| `testReminderSchedule` | 10일째 계산 7가지 (모두 ✅) | 없음 |
| `testMailTemplates` | 리마인드 제목·문구, 사본에 문의번호·이메일 없음 (모두 ✅) | 없음 |
| `testSubmitInquiry` | 문의 1건 + 멘토 메일 + `TEST_STUDENT_EMAIL`에 사본 | 2통 |
| `testSendReminder` | 가장 최근 답장 전 문의 1건에 리마인드를 바로 보냄 (10일 안 기다림) | 1통 |

실제 확인 순서
1. `testSubmitInquiry` → 멘토 메일함에 `[꾸로록 문의] 테스트 문의입니다`, 학생 메일함에 `[꾸로록 보낸 문의] 테스트 문의입니다`가 왔는지 (스팸함도).
   - 사본에 멘토 이름·내용·보낸 일시가 있고, 문의번호·멘토 메일 주소가 **없는지**.
2. (제한이 켜져 있을 때) **10분 안에** `testSubmitInquiry`를 4번째 실행 → 로그에 `TOO_MANY_REQUESTS`와 "현재 메일 발송량이 많아 전송이 잠시 제한되었어요. 10분 후 다시 시도해 주세요."가 나오면 정상 (메일 안 나감).
   - 테스트 기간에는 설정 탭 `rateLimitMinutes`·`rateLimitPerDay`를 `0`으로 두고, 운영 전에 `10`·`5`로 되돌립니다.
3. `testSendReminder` → 멘토 메일함에 `[꾸로록 리마인드] 테스트 문의입니다`가 오고, 맨 위에 리마인드 문구가 있는지. 문의 탭 그 줄의 `리마인드일시`가 채워졌는지.
4. 멘토가 **리마인드 메일**에서 '답장' → 5분 기다리거나 메뉴 → 답장 지금 확인 → 학생에게 전달되는지, 리마인드 문구가 학생 메일에 **없는지**.
5. 메뉴 → **상태 보기**: `답장 자동 확인 트리거: 1개`, `리마인드 트리거: 1개`, 제한·리마인드 숫자가 맞는지.

> 리마인드 트리거는 "매일 10시~11시 사이"처럼 1시간 범위 안에서 구글이 시각을 정합니다. 정확한 분은 정할 수 없습니다.

## 10. 알아 둘 한계 (MVP)

- Gmail 중계는 스팸함에 들어갈 수 있고 하루 발송 한도(약 100통)가 있습니다. 정식 운영 시에는 기관 도메인 + 메일 발송 전문 서비스로 바꾸는 것을 권장합니다.
- 멘토가 **'답장' 버튼**으로 보내야 학생에게 전달됩니다. 새 메일로 보내면 전달되지 않습니다.
- 학생이 전달받은 메일에 다시 답장하는 것(2차 왕복)과 첨부파일은 지원하지 않습니다. 학생의 답장은 중계 메일함에 쌓이기만 하고 멘토에게 가지 않습니다.
- 멘토 답장은 **글자만** 전달합니다. 굵게·색깔 같은 꾸밈과 이미지·첨부파일은 빠집니다.
- 멘토가 답장 본문에 직접 적은 서명·전화번호 등은 그대로 학생에게 전달됩니다. 멘토에게 미리 안내해 주세요.
- 멘토 답장이 중계 계정의 **스팸함**에 들어가면 처리되지 않습니다. 가끔 스팸함을 확인해 주세요.
- 횟수 제한은 학생 메일 주소 기준이라, 주소를 바꿔 가며 보내는 것까지 막지는 못합니다. (사이트 서버에서 IP 기준 제한을 추가로 둘 수 있습니다)
- 학생이 메일 주소를 잘못 적으면 사본과 멘토 답장이 모두 그 잘못된 주소로 갑니다.
- 리마인드를 보내기 전에 멘토를 비활성으로 바꿨다가 나중에 다시 활성화하면, 그다음 날 늦은 리마인드가 나갈 수 있습니다.
